Step-by-step: what enters, happens, and leaves

These are the active calls made by ontology.py, in execution order. Helpers are grouped under the stage that calls them.

0. Start and open the graph

ontology.py:main() owns the run and the only per-file loop.

receivesCLI source path, optional graph path, optional -v. callsgraph_management.open_graph(), which binds prefixes and parses existing Turtle or creates the base seed in memory. returnsThe current rdflib.Graph. Opening a missing path does not save it yet.

1. Discover and read sources

ingest_sources.py turns a path into a stable stream of text.

receivesSource path and output graph path. callsfind_text_files() recursively scans supported extensions, sorts paths, and excludes the output graph; read_source() reads UTF-8 with replacement. returnsOne raw text at a time. Whitespace-only text immediately skips the rest of the loop.

2–3. Understand the source and select graph context

task_context.build_task_context() composes the source-only and graph-only branches.

sourcesource_concepts.extract_source_concepts() extracts deterministic mentions, phrases, and keywords. text_phrases() supports whole-word matching. graphontology_views.build_ontology_views() derives the five read-only views; entity_lookup.entity_catalog() supplies native entity identities. selectsselect_task_context() uses direct tiers 1–4, then expand() adds bounded dependencies and one-hop neighbors at tiers 5–8. returnsContextPackage: concepts, schema, patterns, resources, examples, labels, diagnostics.

2a. Derive five views from the current graph

ontology_views.py is the façade used inside context selection.

partitiongraph_partition.partition_graph() classifies every triple into disjoint schema, instance, or support graphs. declaredgraph_skeleton.create_graph_skeleton(schema) copies the explicit class/property core and complete supported restrictions. It infers nothing. observedgraph_patterns.observed_relationships(schema, instance) calculates class–property–range usage evidence and cardinality statistics. returns{schema, instance, support, skeleton, patterns}. None is cached between source files.

4. Render and fit the prompt context

context_render.prepare_prompt_context() turns structured selections into safe, bounded prompt text.

rendersrender_context_items() writes declared, observed, resource, and example blocks; assemble_context() keeps that authority order visible. budgetsbudget_for() adds source token cost. allowance() chooses the smaller limit; prompt_budget.fit_context_items() keeps complete dependency bundles only. returnsContext text, budget diagnostics, and only the native existing_ids whose resource cards survived packing.

5. Build the extraction prompt and ask the model

source_parse.py owns the extraction contract; llm.py owns the network boundary.

promptmake_prompt() combines source, selected context, context rules, exact JSON shape, endpoint rules, and required confidence. requestparse_source() calls llm.ask_llm(); model_name() loads the configured OpenRouter model; temperature is zero. returnsParsed but untrusted JSON with entities[], relations[], and facts[].

6. Validate and normalize the complete response

candidate_validation.validate_candidates() is a read-only structural gate, not an identity matcher.

checksContainers and fields, local ID grammar, text normalization, endpoint references, allowed existing_id values, numeric confidence, duplicates, generated-URI roles, and property type collisions. validReturns normalized candidates plus warnings and counts. invalidformat_validation_failure() raises a run-stopping error. Planning, applying, and saving do not run for that file.

7. Decide identity and every merge outcome

merge_policy.py plans everything against the complete graph without mutating it.

originbuild_provenance() records source path/digest, model, and policy version. identityresolve_entities() calls entity_lookup.entity_catalog() and identity_decision() for existing/new/review decisions; planned new entities form a virtual catalog. assertionplan_graph_merge() decides accept/duplicate/review, preserves existing canonical values, and creates deterministic audit triples. returnsA complete MergePlan: identities, field decisions, relation/fact outcomes, domain triples, audit triples, counts, diagnostics.

8–9. Apply the plan to a copy, then save atomically

Mutation starts only here, after every policy decision is complete.

copygraph_merge.apply_merge_plan() creates a new graph, copies namespaces and all current triples, then adds only the plan's domain and audit triples. It contains no identity or conflict logic. savegraph_management.save_graph() serializes to <path>.tmp and replaces the target with os.replace(). Failed serialization leaves the old file usable. continueOnly after save succeeds does graph = updated. The next source file rebuilds context from this larger graph.

Merge policy: the decision order matters

For a valid package, the planner checks outcomes in this order. An earlier result wins; later rules do not override it.

1 · identity usable?Ambiguous exact name, kind collision, close spelling, or low-confidence new identity goes to review.
2 · exact duplicate?An existing triple is corroboration, even when confidence is below 0.80. It is not re-added.
3 · explicit conflict?Functional or inverse-functional conflicts go to review. Existing canonical values are never overwritten.
4 · confidence ≥ 0.80?New entities, fields, relations, and facts below the threshold go to review.
5 · acceptAdditive domain triples and deterministic audit triples enter the completed plan.

What the report task adds with -v

Verbose mode exposes the artifacts already moving through the pipeline. It does not alter selection, validation, planning, or saving.

ontology.py reporting lane

Normal mode already prints one-line context, validation, plan, merge, and final totals. Verbose mode expands those checkpoints.

  1. After context selection, report_task_context() prints extracted concepts, graph candidate counts, direct matches, selected items, and reasons. For the declared-core display it read-only rebuilds partition_graph() → create_graph_skeleton() → report_skeleton().
  2. After packing, report_context() lists kept and dropped item IDs; main() then prints the exact prompt-context text.
  3. After the model replies, report_extraction() prints the raw parsed JSON before validation.
  4. After validation, report_validation() prints normalized counts and every warning.
  5. After planning, report_plan() prints each identity target and every entity/relation/fact outcome with reason codes.
