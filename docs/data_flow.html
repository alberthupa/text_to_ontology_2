The windowed document pipeline that turns text into a growing ontology

The page follows one real run through every transitively related pipeline file. It shows the payload passed between methods, the read-only context branch (canonical plus (this document) staging), the validation and repair gates, the source-local admission loop, the two complete-source SHACL gates, the one canonical identity pass, and the single atomic publication — or, with --dry-run, the same plan without writing.

text-to-ontology <source file or directory> [ontology.trig] [-v | --report] [--dry-run]
M7 document publication windows with token overlap read-only plan before mutation one atomic publish per non-empty file
One document transaction A document's windows only ever write to its own source staging graph (provisional IRIs). After the last window, source_reconciliation.py reports the complete source, source_validation.py gates it with SHACL, document_merge.py resolves identity exactly once against the canonical scope, and document_publication.py replaces target, provenance, and review graphs in one Publication. The final dataset is byte-identical on any validation or publication failure.

Step-by-step: what enters, happens, and leaves

These are the active calls made by pipeline.run_text_to_graph(), in execution order. Helpers are grouped under the stage that calls them.

0. Start and open the dataset

cli.main() builds adapters and calls the one public API; the pipeline owns the loop.

receivesCLI source path, optional graph path, optional -v, --report, --dry-run. callsgraph_store.initial_role_graphs() reads schema / shapes / data / provenance / review; a wholly fresh store gets the virtual seed (schema + embedded EntityShape). returnsThe union graph used for context and identity. A missing dataset is seeded in memory; nothing is written yet.

1. Discover and read sources

ingest_sources.py + windowing.make_source_document() turn a path into a stream of documents.

receivesSource path and output graph path. callsfind_text_files() (recursive, sorted, extension-filtered, graph-excluded); read_source() (UTF-8, replacement); make_source_document() (content-derived doc-sha[:16]). returnsOne document at a time. Whitespace-only files immediately skip the rest of the loop.

2. Plan reproducible windows

windowing.plan_windows() is source-only: text, digests, offsets.

splitsBlock spans (headings/paragraphs) first; oversized blocks fall back to sentences, then to hard character chunks. packsGreedy unit packing with token overlap (default target 800 / overlap 100). A short document stays one whole-text window; blank documents produce none. returnslist[TextWindow]. Spans tile the normalized text (nothing dropped or duplicated), so the document tail is never lost.

3. Select layered context per window

source_staging.layered_context_text() combines two read-only selections into one budgeted block.

canonicaltask_context.build_task_context(window_text, final_graph) — direct tiers 1–4, then bounded expansion 5–8. sourceThe same selector against this document's staging graph; every rendered line is prefixed (this document), and its resources are forced non-native. budgetsOne shared allowance (context_render.allowance() − assembly_overhead()); fit_context_items() keeps complete dependency bundles only. Only canonical native resource cards can become reusable existing_ids. returnsContext text, budget diagnostics, and the surviving existing_ids.

4. Build the prompt and ask the model (with repair)

source_parse.make_prompt() renders the named extraction_user template from prompts.py (a studio-editable template, overrides in prompts.local.json); repair.extract_validated() bounds how messy answers are handled.

promptmake_prompt() combines source, selected context, context rules, exact JSON shape, endpoint rules, and required per-record confidence. requestOpenRouterExtractor.extract() → llm.ask_llm() (temperature 0, 60 s timeout). repairAn unparseable or contract-violating answer is sent back with its deterministic issue list for a corrected JSON, up to repair_attempts (default 2, 0 disables). returnsParsed but untrusted JSON with entities[], relations[], facts[].

5. Validate and admit one window

candidate_validation.validate_candidates() is the read-only structural gate; admission happens against the staging graph only.

checksContainers and fields, local ID grammar, text normalization, endpoint references, allowed existing_ids, numeric confidence in [0,1], duplicates, and generated-URI role/type collisions. data-onlyWith vocabulary=read_vocabulary(graph) (CLI --data-only, always on in the studio) an undeclared kind or predicate is an error: the answer is repaired with the declared names, and the starter's classes and relationships can never change. admitsource_staging.plan_window_admission() plans against the staging graph with provisional/<doc>/ IRIs for new entities; candidate_graph.build_candidate_graph() builds the PROV/DQV evidence; graph_merge.apply_merge_plan() grows the staging graph. invalidformat_validation_failure() raises a run-stopping error after repairs are exhausted. The final dataset is never touched.

6. Reconcile the complete source

source_reconciliation.py makes the document's local state explicit.

reportreconcile_document(): local entities, aliases, duplicate assertions with every independent candidate-graph/record/confidence support, unresolved identities, conflicts, counts. artifactbuild_source_artifact(): canonicalized N-Triples plus document digest, graph digest, window-strategy version, candidate-mapping version, extractor identities. returnA plain report dict; RunReporter.reconciliation() prints the summary line.

7. SHACL-validate the complete source

source_validation.validate_source_graph() gates the reconstructed source before any final planning.

shapesExplicit ValidationConfig.shape_graphs, else configured shape roles, else embedded legacy shapes; all combined into one isolated graph. runspySHACL over a copy of the source graph (inference="none"). failsSourceValidationError carries the standard report, the source artifact, the reconciliation report, and (optionally) the staging sidecar. Dataset unchanged.

8. Decide identity once for the document

document_merge.py merges the window packages into one document package and plans against the full canonical scope.

collapsebuild_document_candidates(): safe source-local identities share one record; review-held identities stay separate; exact overlap assertions become one (strongest confidence wins). resolveplan_document_merge() calls merge_policy.plan_graph_merge() exactly once over schema + data graphs for existing/new/review decisions, accept/duplicate/review assertions, and deterministic audit triples. returnsA complete document plan with an identity_mapping from source keys to final decisions.

9. Compile and publish — or dry-run

document_publication.py builds the exact graph replacement without mutating anything, then makes one atomic call.

compilecompile_document_publication() copies the target graph, adds the plan's domain triples, remaps every PROV/DQV candidate occurrence onto the decided canonical statements, materializes document/file source records and onto:statement/<sha> links, and builds the review graph for withheld candidates. validateThe proposed post-merge data is SHACL-validated; a failure raises PublicationValidationError and nothing is written. publishpublish_document() = one store.publish(Publication) replacing target/provenance/review (schema/shapes/data copied through). --dry-run reports the proposed plan and sizes without this call. continueAfter a successful publish the in-memory roles update, so the next document's context and identity are computed against the larger dataset.

Zoom-in: layered_context_text() → one budgeted block

Every window gets one context block that mixes canonical knowledge and this document's earlier-window knowledge. One budget controls the whole block; it does not shorten the source and does not directly limit the model's response.

effective context budget = min(context_tokens, max(0, total_limit − fixed_prompt_tokens − source_tokens − output_reserve − safety_margin)) − assembly_overhead

Canonical items and (this document) staging items are rendered together, priced by the same counter, and only complete dependency bundles survive — least relevant first. Dropping a staging item only loses in-document context; dropping a canonical card removes the reusable existing_id it offered.

What changes in the returned output?

  • text: contains fewer or more complete declared, observed, resource, and example blocks — with (this document) markers on staging items.
  • budget.items / budget.dropped_ids: exactly which bundles survived, in relevance order.
  • budget.used_tokens: item-text cost only; formatting overhead was subtracted before packing.
  • existing_ids: only IDs from canonical native resource cards that survived. Dropping such a card means the LLM may no longer submit that URI as existing_id.

Merge policy: the decision order matters

For a valid package, the planner checks outcomes in this order. An earlier result wins; later rules do not override it. The same planner runs source-locally per window (provisional IRIs) and once more per document against the full canonical scope.

1 · identity usable?Ambiguous exact name, kind collision, close spelling, or low-confidence new identity goes to review.
2 · exact duplicate?An existing triple is corroboration, even when confidence is below 0.80. It is not re-added.
3 · explicit conflict?Functional or inverse-functional conflicts go to review. Existing canonical values are never overwritten.
4 · confidence ≥ 0.80?New entities, fields, relations, and facts below the threshold go to review.
5 · acceptAdditive domain triples and deterministic audit triples enter the completed plan; the document stage remaps evidence and publishes once. In data-only mode no class or property declaration is planned, so only individuals and statements are added, and the class and predicate IRIs come from the starter vocabulary (an imported ontology keeps its own names).

One reporter for -v and --report

Verbose mode exposes the artifacts already moving through the pipeline. -v writes them to the terminal. --report writes them only to a timestamped Markdown file in reports/runs/, keeping a successful terminal run silent. Reporting does not alter selection, validation, planning, or publication.

run_report.py reporting lane

pipeline.py only calls one reporter object. Normal mode produces compact summaries; verbose mode expands the same checkpoints. The reporter writes to replaceable text streams, so terminal and Markdown output do not need separate implementations.

  1. RunReporter.document_staging() announces the document ID, window count, and staging graph name; window_started() names each window.
  2. context_selection() prints concepts, graph candidates, selected items, reasons, and the full declared skeleton used by the selector; it labels that skeleton as not sent wholesale.
  3. prompt_context() prints budget decisions, reusable IDs, and the exact selected context text (canonical + (this document) items).
  4. llm_input() prints the exact system and user messages sent to the extraction LLM; model_replied() prints the parsed but still untrusted extraction record by record, with repair attempts reported.
  5. validation() prints pass/fail, normalization and duplicate counts, and path-addressed errors or warnings; window_admitted() reports what entered the staging graph.
  6. reconciliation(), source_validation(), merge_plan(), and publication_validation() print the two SHACL results, identity methods, field and assertion outcomes, reason codes, conflicts, and counts.
  7. saved() / dry_run() report the atomic publication or the plan that deliberately was not published.

Talking to the graph: a third read-only consumer

The graph chat is the same selection idea applied to a question instead of a source text. graph_scope.select() reuses task_context to find what the question is about, collects the statements around those resources (types and labels first, a slice reserved for the declarations), caps the result by whole triples, and hands back three faces: TriG for the viewer, a view directive for the frontend, and compact lines for the model. Nothing here writes, and the transcript keeps the subgraph behind every answer, so what the model saw is always visible. The pipeline above is untouched.

What a model is actually handed is the scope's rendered text, and that has its own token ceiling: a PREFIXES block, a NAMES block (each label once), then short statements. Whole triples are dropped when the ceiling is reached and the count is reported, so a partial view of the graph is visible to the reader as well as to the model.

Editing the graph: a fourth writer, previewed first

A hand edit or a chat proposal is a patch: additions are Turtle, removals are the same statement with - in front. graph_edit.preview() parses and checks it (new vocabulary is refused unless the toggle is on, undeclared names are refused while the vocabulary is frozen, SHACL violations are warnings) and stores the exact triples under a patch id; graph_edit.publication() then writes those stored triples into the target graph and adds one prov:Activity plus an rdf:Statement per triple to the provenance graph, in the same single atomic publish() the pipeline uses. Schema, shapes and review graphs are never touched by an edit.

Active files and their main methods

This is the transitive execution path of the CLI. Viewer/report-generation files are separate read-only tools (view_ontology.py, view_report.py, view_html.py) and are not called by this command. Everything a frontend can ask for is a named operation (operations.py): one registry, one generic HTTP path (/api/op/<name>), and the page only draws what comes back. The state and the two long jobs live in workspace.py; studio.py is transport only. Two further entry points wrap the same loop: starter.py (paste → checked starter ontology → one atomic publication) and studio.py (local page + API that creates the starter, ingests dropped files data-only, and resets), which read the frozen vocabulary through vocabulary.py.
