Notes from my 1:1 with Tomasz Rostkowski

Our offering consists of different components that are very connected with each other and sometimes overlapping. We need to map them properly and align how we structure the offering, so that there is clear split but also reference to complementary elements:
- Reasoning Agents
- Talk to Data
- Chatbots / Voice bots
- Knowledge and context management
- Adoption and evaluation
- Agentic Architectures
- Process generation vs. content automation

High level plan for the talk-to-data offering:
1. Why - what is the challenge today and the opportunity - people no longer just want dashboards and reports they want to be able to interact with the data, etc. 
2. What is talk to data and what are the types (structured vs. unstructured, RAG, nl2sql)  
3. Modality - text vs voice chatbots
4. Additional tools that talk to data may use
5. Technology behind it - from no code through low code to bespoke - on Azure, GCP
6. Technical componenets - RAG semantic layer etc
7. How we deliver such projects - UX/UI, evaluation, adoption
8. Case studies
9. How to scale talk-to-data (multiple t2d solutions) - nawiazanie do Agentica?
